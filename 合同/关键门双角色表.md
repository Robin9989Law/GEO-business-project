# 关键门双角色表

与 `agent_pm/engine.py` 的 `GATE_DUAL_APPROVERS` / `GATE_REQUIRED_ROLES` 一一对应。未列入本表的门单签即可，签字角色默认「负责人」。

| 门 | 阶段 | 第一角色 | 第二角色 | 必须两人 | 审计包 |
|---|---|---|---|---|---|
| G0 | 01 | 负责人 | — | 否 | `decision_reason` 建议填；`required_outputs` 由注册表推导为 `01_商机卡` |
| G1 | 02 | 负责人 | GEO/验收专业复核 | 是 | 必须 `decision_reason`；必需件 `02_章程` `02_验收标准` `02_需求规格` |
| G6 | 07 | 负责人 | — | 否 | `07_预算` |
| G7 | 08 | 客户成功 或 负责人 | — | 否 | `08_沟通矩阵` `08_干系人` |
| G3 | 03 | 负责人 | 测量复核 | 是 | 必须 `decision_reason`；`03_冻结包` `03_环境登记` `03_出数报告`；`evidence_checksum` 默认 `config_checksum` |
| G2 | 04 | 负责人 | — | 否 | `04_进度` |
| G5 | 05 | 负责人 | — | 否 | `05_周报`；冲刺另加 `05_干预轮次卡` |
| G4 | 06 | 负责人/客户成功 | 测量复核 | 是 | 必须 `decision_reason`；`06_客户报告` `06_验收单`；`evidence_checksum` 默认交付哈希 |
| G8 | 09 | 负责人 | 文件/资产复核 | 是 | 必须 `decision_reason`；批准前 `out/09_*.md` 三件已齐 |

## 规则

1. 关键门（G1 / G3 / G4 / G8）必须两个**不同成员**、两个**规定角色**都签字，第一次记 `PENDING_DUAL`，第二次才过门。
2. 第二次签字不得用空的 `required_outputs` / `hard_check_results` / `quality_review_id` / `evidence_checksum` / `decision_reason` 覆盖第一次留下的审计信息。
3. `required_outputs` 一律从 `合同/阶段交付物注册.md` 推导，调用方不必手填；缺件则该门不得 APPROVE。
4. 角色代号只用本表与 `成员登记.csv` 中的名称：负责人、GEO/验收专业复核、测量复核、文件/资产复核、客户成功、操作员、评分、编排。
5. Agent 不得 `APPROVE`。人签字时必须带 `--member` `--role`（关键门），以及 `--decision-reason`。

## 操作示例

```bash
python3 agent_pm/run.py decide CASE --gate G1 --verdict APPROVE --actor human \
  --member owner_a --role 负责人 --decision-reason "章程与验收字段已锁"

python3 agent_pm/run.py decide CASE --gate G1 --verdict APPROVE --actor human \
  --member owner_b --role GEO/验收专业复核 --decision-reason "专业复核通过"
```
