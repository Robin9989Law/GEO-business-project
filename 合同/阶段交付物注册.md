# 阶段交付物注册表（Stage Deliverable Registry）

全流程 01→09 唯一正式的「可发布 doc_id」清单。正式发布（`promote_formal`）的 `doc_id` 必须在本表声明；未声明的文件即使在 `out/` 也不会被升正式版（避免「文件名以阶段号开头就自动升正式」的隐患）。

字段说明：

- `stage`：所属阶段（对应 `STAGES = ("01", "02", "07", "08", "03", "04", "05", "06", "09")`）。
- `doc_id`：正式件唯一标识；同 stage 不可重复；发布时引擎只认本表。
- `required`：`是` 则该 stage 过门（G*）必须存在此 `doc_id` 的现行件。
- `gate`：绑定门（同一件只许挂一门）。
- `human_inputs`：人需要交什么原始件（路径形态）。
- `quality_dimensions`：Agent 质检维度。
- `evidence_path`：证据存放位置（测量实物仍在 `流程/03 测量/`）。
- `checksum_field`：本表为基线；正式件 `manifest_checksum` 须能复算。
- `approver_role`：批准人角色（关键门须双签；详见 `合同/关键门双角色表.md`）。
- `handoff_readable`：下一站可读字段清单。
- `must_not`：本 doc 不得包含的内容。

## 注册表读法

- `promote_formal` / `promote_stage_outputs` 在写入 `正式/清单.csv` 之前查本表；`doc_id` 不在表内 → `_fail("doc_id not in registry")`。
- 同 stage 多 `doc_id` 视为并行件；过门判定以 `required=是` 的 `doc_id` 是否全部存在现行件为准。
- `gate` 字段必须与 `GATE_AFTER[stage]` 一致；不一致视为发布门错误。
- 模板原件只允许花括号占位（见 `核心合同.md §0`）；具体客户事实不得直接入注册表或清单。

## 与其他文件关系

- 战略口径：`合同/核心合同.md §1` 字段表。
- 阶段模板：每阶段 `模板_*.md`（`流程/0X .../模板_*.md`）；模板的产物文件名 = `doc_id`。
- 阶段 AGENT：`agent_pm/agents/0X_*.md`；Agent `apply` 时按本表过门。
- 门定义：`合同/项目流程SOP.md §3` 门表。
- 关项字段：`close_assets_ok` `close_no_reopen_l1` `close_manifest_ok` `close_board_empty` `close_archive_ok`（见 `09_close.md`）。

## 维护规则

- 新增 `doc_id` 必须改本表，并在 PR 中给出"为什么需要这件 + 哪一门的产物 + 证据路径"。
- 删除 `doc_id` 必须先确认所有案件的 `正式/清单.csv` 都不再以该 id 为现行件。
- `must_not` 字段是门禁语言；任何 `promote` 扫描到对应词直接 fail。
