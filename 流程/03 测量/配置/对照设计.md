# 监测设计（必须和 project.csv 一起读）

当前默认：`control_design=same_category_unmatched_jobs`，`causal_claim=descriptive_until_isolation`。

H01–H06 是**监测组**，用来看同品类溢出和同向漂移，**不是反事实对照**。

## 处理组

`need_id` N01 / N02 / N03：叉车证的发现、对比、品类入口。本轮可以做一类证据干预。

## 监测组

`need_id` H01–H06：仍是叉车证、同一座城，作业换成补证、复审、报考资格、异地互认、查询官网。每个 need 至少 2 条不同 style 的释义。本轮不优化这些页面。

监测组与处理组同品类，内容干预可能同时抬高 H 组。因此 H 组只能检测溢出，不能当作「假如没干预会怎样」。

## 为什么不用跨品类作业

旧 Holdout（电工/焊工/高处作业）与处理组不是同一检索市场，连溢出监测也不成立。

## 还不能叫 DiD 的原因

没有城市/市场隔离或分阶段 rollout 之前，复测只许写「受控前后描述」。监测组涨或没涨，都不能单独证明因果。

## 何时才能勾确认性 L1

1. `control_design` 改为 `matched_need_randomized` 或 `geo_rollout`，并且写清隔离方式。  
2. 至少两个干预前日期、一个干预后日期。  
3. `metrics_rollup.py --did-pre --did-post --case-id --project-id` 输出的 DiD 95% CI 不含 0。  
4. 主终点只有 `p_mention`；`p_recommend` 是次要终点，用 Holm 校正。
