# 8. 问法扩写（只进 explore）

把一条种子问法扩成用户会打的乱问。**禁止**把结果写进 core / holdout，除非负责人冻结新一轮。

```text
你在扩 GEO 测量词表，不是在写提示词，也不是在优化 SEO 标题。

【种子】{{seed_text}}
【城市】{{city}}
【品类口头说法】{{aliases_for_category}}   # 如：叉车证 / 叉车本 / 铲车证 / 特种证

【要覆盖的乱法】每种至少 2 条，一共 16–24 条：
- fragment：残句、没主语、没问号（叉车证呢、哪儿办）
- typo：错字、同音、输入法（插车证、报吗、石狮打成石师）
- slang：口语、微信腔（靠谱不、坑不坑、包过吗、亲）
- voice：像语音转文字（附近有没有那个开车的证怎么弄）
- mix：一句里混价格+靠谱+地点+材料
- wrong_word：用错品类词但意图仍是种子（驾照/资格证/上岗证）
- groupchat：群里复制（有人知道…吗 急）

【硬规则】
1. 必须像真人随手打的，不要排比、不要「如何办理XXX指南」。
2. 不要补「请联网」「请列出三家」。
3. 不要写成客服话术或广告。
4. 不要出现未确认的价格、通过率、包过承诺（问可以问「包过吗」，答不是你的事）。
5. 只输出 CSV 行，含表头：
query_id,text,set,intent,locale,treat,active,style,branded,kumar_cat,need_id,paraphrase_id,persona,asset_class
set 一律 explore，treat 一律 0，active 一律 1，branded 一律 0（除非种子本身点名客户）。
asset_class：无品牌 = vertical_public；点名客户 = client_only。
query_id 用 {{prefix}}01 起。
intent 从 locale/compare/qualify/category/risk 里选最接近的一个。
同一信息需求共用 need_id，paraphrase_id 从 1 递增。persona：groupchat→group，voice→voice，其余 default。
6. 扩写是新释义，不是把 core 改写后再冒充同一 query_id。
```
