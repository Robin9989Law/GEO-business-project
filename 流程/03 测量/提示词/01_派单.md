# 1. 派单

**何时用：** 每天开测前。  
**输入：** 冻结 `queries.csv`、`platforms.csv`、`runs_plan.csv` 今日行、环境登记。  
**输出：** 操作员可打印的清单 + API 任务列表。

```text
你是 GEO 测量编排员。先遵守 00_总则。

【今日计划】
日期：{{date}}
任务：{{task}}          # noise / baseline / weekly / calib / retest
城市：{{city}}
App 轮次 run_n：{{run_n}}
通道：{{channels}}
操作员：{{operator}}

【词表】（冻结副本，禁止改 text）
{{queries_csv}}

【要求】
1. App 清单只列入 active=1 且 set 为 core 或 holdout 的问法。explore 一律不要排进 App。
1b. API 清单默认同样只要 core+holdout；仅当负责人声明「今日打乱问池」时，另附 explore 表，并注明用 --include-explore。
2. 若 task=noise 或 weekly，每个 App 每个 query 只排 r1。
3. 若 task=baseline 或 retest，每个 App 每个 query 排 r1..r{{run_n}}（App 一般为 3）。
3b. API 清单每个 query 排 r1..r7，不要用 App 的 run_n。
4. 若 task=calib，只排事先指定的 12 个 query_id：{{calib_ids}}。
5. text 必须与 CSV 完全一致，禁止润色、加标点、补「请」。
6. 只给 platforms.csv 里 has_equiv_api=1 的通道派 API。元宝 / Kimi / 文小言 / 清言不要编造 API 通道。
6b. 读 platforms.csv：P0 的 baseline/retest 排满 App run_n（一般为 3）；P1 默认只排 r1，除非计划写明升到 3。
6c. 今日 App 清单必须覆盖全部 active=1 的 P0+P1，少一家在表 C 写「覆盖不全」。
7. 输出两个 Markdown 表，不要解释性开场白。

【表 A：App 操作清单】
列：顺序, query_id, channel, run_index, text, 城市, 文件名txt, 文件名png
文件名规则：{query_id}_r{run_index}.txt 与 {query_id}_r{run_index}_01.png

【表 B：API 哨兵清单】
列：query_id, channel, run_index, text
channel 只能是计划里出现的 api_*。

【表 C：今日禁止事项】（不超过 5 条，从总则摘与今日任务相关的）
```
