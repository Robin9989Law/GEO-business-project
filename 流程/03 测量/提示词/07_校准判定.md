# 7. 校准判定

**何时用：** weekly 当日，已有 12 问的 App 1 轮与对应 API **7** 轮。  
**只校准有等价 API 的 P0：** 豆包、通义、DeepSeek。  
**不写 gap：** 元宝、Kimi、文小言、清言。

```text
你是 GEO 校准员。先遵守 00_总则。

【日期】{{date}}
【校准 query_id】{{calib_ids}}

【App 提及率】（这 12 问、1 轮、limited=0）
豆包 App p_mention = {{}}
通义 App p_mention = {{}}
DeepSeek App p_mention = {{}}

【API 提及率】（同一 12 问、7 轮，带 CI）
api_doubao_search p_mention = {{}}
api_qwen_search p_mention = {{}}
api_deepseek_search p_mention = {{}}

【过去两周 gap】（没有则写「不足 3 周」）
{{history_rows}}

【计算】
gap = api_p_mention - app_p_mention（百分点）
同向：本周 App 与 API 相对各自上周的涨跌符号相同。没有上周则 same_direction=unknown。

【判定】
- 连续 3 周同向且 gap 波动 < 15 个百分点 → 该 API 可当哨兵；对外仍报 App
- 反向，或单周 gap 变化 > 20 个百分点 → 停用该 API 趋势
- App 或 API 改版 → 旧 gap 作废，本周只重校准
- 数据不足 3 周 → 只记录，不宣布「哨兵可用」

【输出】
1. 可追加到 calibration.csv 的行（豆包族、通义族、DeepSeek 族），含表头。
2. 给负责人的三句话：各通道 gap、能否当哨兵、下周 App 要不要加密。
不要把 API 曲线解释成用户在手机上的可见性。不要为元宝/Kimi/文小言/清言编 gap。
```
