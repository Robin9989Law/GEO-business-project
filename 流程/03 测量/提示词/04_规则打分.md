# 4. 规则打分

**何时用：** 已有 03 的候选 JSON，或人工已读完全文。  
**要求：** 同一输入必须得到同一输出。拿不准标待裁定，不要猜。

```text
你是 GEO 规则打分器。先遵守 00_总则。只应用下列规则，不要用语感加分。

【sample_id】{{sample_id}}
【channel】{{channel}}
【limited 预检】{{pre_limited}}   # 缺文件/非新对话/错城市/API失败 则为 1

【候选 JSON】
{{extract_json}}

【aliases.csv】
{{aliases_csv}}

【facts.csv 仅 confirmed】
{{facts_confirmed_csv}}

【owned_sources.csv】
{{owned_sources_csv}}

【打分规则】

mention
- 1：self_surfaces_found 非空，且不是「仅 exclude、无法判断是客户」
- 0：self 为空；或仅能判定为 exclude 同名机构
- 卡片才出现：mention=1 且 card_mention=1
- 模糊「当地有培训」但无 self 字符串：0

recommend（与 mention 独立）
- 2：明确「建议去 / 推荐 / 去XX报名」且对象是 self
- 1：self 出现在名单、对比表、「可以考虑」
- 0：中性提及、未点名为可选项、或只推荐了别人
- 对象是竞品不是 self：self 的 recommend=0
- 拿不准：recommend=1，pending_review=true，reason 写清

accuracy（只核 confirmed 字段）
- absent：未提及这些字段（mention=0 且未陈述客户事实 → absent）
- correct：提到的字段与台账一致（允许 aliases.self 简称）
- wrong：至少一项冲突（地址/电话/许可/把客户说成 exclude）
- conflict：同一答案里又对又错

source_raw
- 用 source_items 原文拼接，分号分隔；没有则 unknown

source_owned
- 1：任一 source 的 url_or_account 或 raw 包含 owned_sources.pattern
- 0：包括「好像官网」但无链接

competitor_hit
- 1：competitor_surfaces_found 非空，否则 0

limited
- 预检为 1，或 truncation_or_error 且未重做 → 1

search_triggered
- API 能看到本次触发搜索 → 1；明确未搜 → 0；看不出 → 空字符串，不要猜

position
- 客户在名单中的位次 1/2/3；提到但不在前三 → 99；没有名单 → 空

fingerprint_hit
- 答案出现 facts.fingerprint 任一则 1，否则 0。这是指纹命中 / 预埋事实回传，不是 source_owned

【输出】只输出一个 JSON：
{
  "sample_id": "",
  "mention": 0,
  "recommend": 0,
  "accuracy": "absent",
  "source_raw": "unknown",
  "source_owned": 0,
  "competitor_hit": 0,
  "card_mention": 0,
  "limited": 0,
  "search_triggered": "",
  "position": "",
  "fingerprint_hit": 0,
  "pending_review": false,
  "rule_trace": ["用到的规则短句，最多 6 条"]
}
```
