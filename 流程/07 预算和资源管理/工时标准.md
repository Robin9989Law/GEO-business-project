# 工时标准（通用）

按「激活问法数 × 平台数 × 本产品线允许轮次 × 角色」估 App 冷问，不要抄某一品类的历史人天或公开 MMRE 当定额。

- 单次有效冷问（含截图入库）：按现场标定，未标定前用 3–5 分钟 / 次作计划假设，并在预算表 note 标明「假设未标定」。
- 评分：正式行五指标，计划按冷问时间的 0.5–0.8 倍。
- 基线 / 复测 Core 抽检：与评分同量级，须第二人。
- API 哨兵：脚本跑，编排盯失败；不按 App 人天计。
- 改问法后的重冻与重基线：整段基线人天再计一次。

报价不得把「决策级」或「确认性 L1」写成默认交付。

## 合同字段（07 写入）

| 字段 | 含义 |
|---|---|
| `budget_hours` | 本案计划人天，按激活问法 × `platforms_required` × 允许轮次 × 角色 |
| `budget_scope` | 等于锁定的 `sop_stage` 允许集：诊断 / 冲刺 / 续约 |
| `quote_excludes_l1` | 必须为「是」 |

诊断的 `budget_scope` 不得含干预、一类证据、改页。04 进度人天不得超出 `budget_hours`。
