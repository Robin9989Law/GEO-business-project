# 10 项目文件 · 节点提示词（全程）

先读仓库根目录 `AGENTS.md`，再读本页和 `规则.md`。本目录不是 09 之后多一站，是 **01–09 全程的文件工作区**。开单时就建，结项时才封。

人只交文件、在门上拍板、在中转里取件。你做：入库、发布正式版、刷新看板、卡住禁售句。

## 三件事（缺一不可）

| 功能 | 人做什么 | 你做什么 | 路径 |
|---|---|---|---|
| 1. 原始资料 | 按当前节点说明书交材料 | 原样收入 `原始/{阶段}/`，写 `原始/登记.csv` | `流程/10 项目文件/案件/{本案}/原始/` |
| 2. 正式文件配置与版本 | 批门 / 要求改 | 过门后发布到 `正式/现行/`，旧版进 `正式/版本/vNNN/`，更新 `正式/清单.csv` | 不得原地覆盖现行 |
| 3. 成员中转与交互 | 把要给同事的文件丢给你，或按看板去取 | `drop` → 看板变红；对方 `pick` / `ack`；每次开口先读看板 | `流程/10 项目文件/案件/{本案}/中转/` |

测量实物（冷问 txt/png、台账）**留在** `流程/03 测量/`，这里只登记指针，不复制截图。

## 你在哪

全流程并行层。当前业务站仍由 `state.json` 的 `stage` 决定；本页决定「这份东西放哪、算不算正式、谁能改」。

上游：`init` 已建本案库。  
下游：09 收尾抽查本库无客户事实泄漏；`close_assets_ok` 要看这里。

没有单独的新门。正式发布挂在已有门上：G0–G8 批准的那一批 `out/` 自动升正式版。

## 先弄清的情况

- 这是原始（人刚交、未过门）还是正式（已过门、对外/对内可引用）？不要混放。  
- 要改现行正式文件？必须先 `checkout`，改完 `checkin` 出新版本，禁止直接改 `正式/现行/`。  
- 中转看板有没有待取？有则先告诉接收人去取，再谈下一站。  
- 文件里有没有禁售句？原话仍入库到 `隔离/`，正式发布才拒绝。  
- 成员只用代号，不要把真名、客户全称写进通用模板或看板原件。

## 你要做（每轮）

1. 开口先说：业务站在哪；原始放到哪；若看板有待取，先点名谁去取。  
2. 人把材料放到 inbox 或直接交给你后：`deposit` 进 `原始/{当前站}/`。  
3. 人批门后：确认 `out/` 已发布进正式库（`decide APPROVE` 会做）；告诉人现行路径和版本号。  
4. 成员要互传：`drop --from 角色A --to 角色B`，刷新看板，让 B 打开看板取。  
5. 有人要改正式件：先锁，再收新稿，再发布下一版。

可选命令（不是开工前提；没有命令也必须按路径手搬并登记）：

```text
python3 agent_pm/run.py deposit 本案 --src 路径 --stage 01 --title 客户原话
python3 agent_pm/run.py promote 本案 --src 路径 --doc-id 01_商机卡 --gate G0
python3 agent_pm/run.py checkout 本案 --doc-id 01_商机卡 --member 编排
python3 agent_pm/run.py checkin 本案 --doc-id 01_商机卡 --src 路径 --member 编排
python3 agent_pm/run.py drop 本案 --src 路径 --from 操作员 --to 评分 --note 抽检包
python3 agent_pm/run.py pick 本案 --item X0001 --member 评分
python3 agent_pm/run.py ack 本案 --item X0001 --member 评分
python3 agent_pm/run.py board 本案
```

## 需要人做

1. 按当前站 `AGENT.md` 交材料；能丢 inbox，最终必须进 10 的原始库。  
2. 不要自己改 `正式/现行/` 和 `state.json`。  
3. 改正式件前告诉 Agent 谁签出。  
4. 每天或每次开口看 `中转/看板.md`，有自己的待取就取并确认。  
5. 门上仍只说批准 / 驳回 / 要改。

## 材料放哪

## 然后

回到当前业务站的 `AGENT.md` 继续带。本库一直开着，直到 G8 封存。
