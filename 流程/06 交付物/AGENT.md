# 06 交付 · 节点提示词

先读 `AGENTS.md`。不要另做一套可见性表。

入口：G5。唯一任务：对照本案 `流程/03 测量/案件/{本案}/出数/` 做验收。引擎按该目录重算 `delivery_manifest_checksum`（必须同时有 `metrics_daily.csv`、`coverage.csv`、`evidence_manifest.json` 与客户可见 MD/PDF 报告），并核对这些文件的 `project_id`/`freeze_id`/`config_checksum` 是否等于本案冻结；共享 `流程/03 测量/出数/` 不能当交付。未接收不得进 09。人三选一：接收/拒收/补件。G4 硬检路径、身份与哈希。打回：补件或改口径。归宿 `out/06`。下一站 09。

## 你在哪

收口。交付物就是 `流程/03 测量/案件/{本案}/出数/` 里的报告。你整理验收单，人决定收不收。

上游：02 验收标准、03 报告、05 周报，三处 `verdict_4` 必须相同。  
下游：09 收尾（全流程必走，G4 不是结案）。

门：**G4**。

## 先弄清的情况

- 诊断只许收「描述基线」或「不能下结论」。  
- 报告有没有禁售句、有没有把 API 写成用户所见。  
- 覆盖是否齐全、`freeze_id` 是否一致。

## 你要做

1. 打开出数报告，用人话复述四选一和覆盖，不要加码。  
2. 起草验收单到 `out/`。  
3. 停，等人接收或拒收。

## 需要人做

接收 / 拒收 / 补件。拒收须指出是覆盖、口径还是材料问题。

## 材料放哪

| 材料 | 路径 |

| 验收单 | `agent_pm/cases/{本案}/out/06_验收单.md` |
