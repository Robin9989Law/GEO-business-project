## 2. 主题

### 发现与资格（01）

近三年销售研究把「活动量」和「适格」拆开：探查、分类、拒单是门，不是转化承诺。服务化/订阅与一次性卖产品争抢认知资源，一张卡一条产品线。ISO 9001 要求评审与 ISO 20700「不承诺不可控结果」与既有禁售同构：保证推荐必须改口到可观察的提及概率，否则不立项。

### 需求可追踪（02）

需求工程近作反复强调：获取是发现不是收集；自动生成只进原始库；追踪主键必须落到测试/评价对象。对本案：`need_id` 对上 `queries.csv`，处理组与监测组互斥，改 need/平台/验收必须新冻结。未隔离不得把监测组写成反事实。

### 工时与报价边界（07）

软件工时文献一致反对把公开 MMRE、故事点或他行业上浮当定额。规划谬误与「本次独特」会把确认性因果估成便宜交付物。因此人天只能是问法 × 平台 × 允许轮次 × 角色；应急预留必须挂已识别风险；`quote_excludes_l1` 永久为是；诊断骨架不得含干预行。

### 沟通与决策包（08）

权力–利益四分、RACI 单 A、媒介匹配指向同一纪律：指导层收结论包，不收管道日志。API 是采集痕迹，不是用户所见。对外承诺不得高于授权，即不得宽于四选一。口头放宽视为变更。

### 计划与门名（04）

WBS 取向改变网络与工期，产品线必须三张树。PV 来自已授权预算，空包与超预算都不是基线。滚动波把远包留作规划：冲刺复测在 G2 只登记窗与人时，执行在 05。门名统一 **G2**，废除 G2′。

### 控制与 holdout（05）

变更控制是对已批基线的评估/批准；完成日入账后才起等待时钟。产业实验与 holdout 工程文一致：监测组不得再吃处理，短窗不能替代复测。冲刺最终 `verdict_4` 只从本步复测写；诊断整卡无干预。

### 交付完整性（06）

质量门对照本门专属标准；配置项必须标识到基线；发布完整性用哈希拒绝「差不多」。交付物只能是案件出数目录。接收 / 拒收 / 补件三选一，Agent 不得代批。

### 关项与知识（09）

关项对照已接受的输出，不是重新验收。收益实现另立观察账。教训必须改写成可迁移的风险句并脱敏。中转未取、正式清单对不上、未完成项未处置，都不过 G8。禁止用结项重开 L1。

## 3. 对合同的收敛

八站独立映射后，可写入门禁且不互相打架的最小集是：

1. 单产品线 + 禁售改口（01）  
2. need 互斥 + 可灌 03 的追踪（02）  
3. 人天公式 + 排除 L1 + 诊断无干预行（07）  
4. 决策人不以 API 为主表 + 附件顺序（08）  
5. `plan_hours`>0 且 ≤`budget_hours` + 门名 G2 + 复测属 05（04）  
6. 完成日/等待/监测组未改 + 冲刺四选一出自复测（05）  
7. 案件路径 + 校验和 + 接收三态（06）  
8. 四对照 + 脱敏 + 不得重开 L1（09）

厂商百分比、他行业工期/上浮、公开估算误差一律不进合同数字。
