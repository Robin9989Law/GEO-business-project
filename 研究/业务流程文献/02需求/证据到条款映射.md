# 02 需求 · 证据到条款映射

对准合同字段，且必须能灌入 `流程/03 测量/项目接口.md` 的本案 `project.csv` / `queries.csv` / `platforms.csv`。  
博客厂商来源已交叉。标准不占 30 篇。

## 灌入 03 的字段（本站只锁这些）

| 02 锁的字段 | 灌入 03 | 允许值 / 形状 |
|---|---|---|
| `primary_endpoint` | `project.csv.primary_endpoint` | 只能 `p_mention` |
| `causal_claim` | `project.csv.causal_claim` | 默认 `descriptive_until_isolation` |
| `control_design` | `project.csv.control_design` | `监测组`（非反事实） |
| `treat_need_ids` | `project.csv` 且 `queries.treat=1` 的 `need_id` ⊆ 此集 | 非空；与监测组不相交 |
| `holdout_need_ids` | `project.csv` 且 `queries.set=holdout` 的 `need_id` ⊆ 此集 | 可空但冲刺建议非空；与处理组不相交 |
| `platforms_required` | `project.csv` 且 `platforms.csv` active | 默认 P0 全选；禁止平均 |
| `success_rule_diagnosis` | 同名 | 只「描述基线」或「不能下结论」 |
| `success_rule_sprint` | 同名 | 隔离成立且 DiD 95% CI 不含 0 才可称 L1，否则「受控前后描述」 |
| `success_rule_retain` | 同名 | 滚动异常；不重开 L1 |
| 每条 need 的 style 释义 | `queries.csv` 同行，≥2 种 style | 禁止合成一条 |
| RTM 行 | 03 不另建系统；本库登记指针 | 见下表 |

诊断不得在 02 升成冲刺。咨询/报名只观察。

## 三条最强条款（建议写入 02 门禁）

1. **互斥**：`treat_need_ids ∩ holdout_need_ids = ∅`；监测组本轮不优化、不是反事实；未隔离不得写 L1（P15 P19 P20；合同）。
2. **追踪可灌 03**：每条 need 有来源 + ≥2 style + 验收规则指针；主键 `need_id` 对上 `queries.csv`；无来源不得 G1（P07 P18 P25；S01）。
3. **基线即配置项**：改 need / 平台 / 验收必须 CCB + 新 `freeze_id`；未冻结禁止对比（P20 P30；B13 B18；S01）。

不要写入：保证推荐、报名因此增长、API=用户所见、七家平均、未冻结就对比、用结项重开 L1。
