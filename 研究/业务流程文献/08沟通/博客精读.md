### B02 Simply Stakeholders — How to Create a Stakeholder Communication Matrix

- **可用**：矩阵五行：干系人、偏好信道、频率、内容、目的。例：股东季报、高管周报里程碑、客户双周邮件。先分析角色再填格。
- **对应条款**：`comms_cadence` + 沟通矩阵表头。
- **不要抄**：厂商白纸书、AI 情绪分析门槛。

### B01 SixSigma.us — Stakeholder Analysis Matrix

- **可用**：权力/利益四象限：高权高利管紧并参与决策；高权低利 keep satisfied、少细节；低权高利 keep informed；低权低利 monitor。高管要商业影响摘要，技术团队要进度细节。
- **对应条款**：决策人只收四选一；API 属技术细节。
- **不要抄**：Fortune 500 轶事、Belt 证书推销。

### B03 ProjectManager — Stakeholder Matrix

- **可用**：影响–兴趣四分 + 沟通频率/方式。矩阵是登记表的可视化，不是替代登记。
- **对应条款**：`干系人登记.csv` 的 power/interest/report_level。
- **不要抄**：软件试用 CTA。

### B04 Purple Griffon — Stakeholder Analysis Template

- **可用**：分析步骤：识别 → 利益/影响 → 矩阵 → 优先 → 沟通表（对象、会议/邮件、频率）。例行：状态会 weekly。
- **对应条款**：登记表 + 矩阵必须成对。
- **不要抄**：培训课表。

### B06 Asana 2026 — Project Stakeholder

- **可用**：干系人=能影响或被影响者。分析后才调沟通深度。
- **对应条款**：先识别决策人/对接/负责人。
- **不要抄**：Asana 工作流营销。

### B07 ProjectManager — Stakeholder Collaboration & Communication

- **可用**：沟通计划要写升级路径：谁介入、多快响应。另附矩阵：信息、格式、信道、频率、owner。
- **对应条款**：升级行 + 矩阵 owner 列。
- **不要抄**：平台功能清单。

### B09 PL Projects — RACI 问责

- **可用**：R 做事、A 最终负责（每任务仅一人）、C 决策前咨询、I 单向知情。PMI 转述：角色清晰的项目达成目标概率高约 40%（二手数字，只作方向）。RACI 是治理工具不是图表收藏。
- **对应条款**：决策人 = A（四选一）；对接 = I；班组 = R。
- **不要抄**：40% 写进合同。

### B10 ITONICS — Decision Rights, RACI, Program Management

- **可用**：决策权先于 RACI；单工作流可逆决策归项目经理，跨依赖/战略归项目群，资本再分配归赞助人。决策日志：决定了什么、谁有权、约束是什么。Kick-off 就写，事后补治理成本高、采纳率低。每决策只一个 A，C 不超过 3。
- **对应条款**：G7 前锁决策权；纪要必记授权人。
- **不要抄**：Deloitte 23% 营收等厂商二手统计。

### B12 Invensis — RACI step-by-step

- **可用**：先列可交付物再填 RACI；A 不能空、不能两人。
- **对应条款**：四选一的 A 只能是 `stakeholder_decision`。
- **不要抄**：课程推销。

### B13 Plane — RACI charts

- **可用**：RACI 在执行中当导航，不进共享盘吃灰。
- **对应条款**：矩阵放 `正式/现行/`，改走版本。
- **不要抄**：Plane 产品句。

### B15 Institute of Project Management — RAM

- **可用**：责任分配矩阵 = 任务 × 角色。与组织层级不同：职称不等于本案任务权限。
- **对应条款**：通用模板不写真名，写角色代号。
- **不要抄**：证书路径。

### B11 ProjectManager 2026 — Escalation Matrix

- **可用**：升级矩阵含：文档控制、范围、角色（可挂 RACI）、原则（先最低层解决、按影响不按职称、无指责、时限）、优先级、触发阈值、层级、联系人、工作流。例：关键 24h / 高 72h；预算偏差 >10%；关键路径延误 >3 天。
- **对应条款**：口径争议、API 被当成主表、口头放宽四选一 → 立即升级到决策人/负责人，不在对接层「先这么对外说」。
- **不要抄**：$50K 安全阈值（他行业）。

### B16 Plane 2026-01 — Project escalation procedures

- **可用**：升级 = 当前权限/时间/资源不够时把问题交给有权决定的人。区别：issue 在团队内解决；risk 面向未来；escalation 要的是决策。不是问责仪式。
- **对应条款**：监测组异常、噪声未完成就解释涨跌 → 升级，禁止周报先下结论。
- **不要抄**：Plane 试用。

### B17 PMI — How to Run an Effective Status Meeting

- **可用**（official）：状态会按听众裁剪；不是读屏幕；会前用工具收更新。与「报告 ≠ 沟通」（Bourne）一致：报告是时间序列，沟通是有目的的。
- **对应条款**：决策人会议只呈四选一；细节会留给内部。
- **不要抄**：PMI 课程广告。

### B22 TeamGantt 2025-02 — Status meetings for every audience

- **可用**：五类会：每日站会 15min（卡点）；团队周会 30–60min；内部干系人双周 30–45min；高管月/季 30min 只要风险与战略决策；客户双周。高管会禁止任务清单。
- **对应条款**：`comms_cadence` 默认：门时决策人、每周对接、采集日班组。
- **不要抄**：Gantt 产品。

### B18 ProjectManager 2025-05 — Decision Log

- **可用**：日志是沟通工具：谁授权、为何、备选、影响、签字。会后和走廊决定都要记。修订本身也是一条决定。
- **对应条款**：`模板_会议纪要.md` 的「决定 / 与测量不一致的口头承诺作废」。
- **不要抄**：软件任务列表当日志。

### B19 monday.com 2026 — Decision Log

- **可用**（vendor）：字段：摘要、理由、备选、批准人、日期。单一事实源，避免聊天里找决定。
- **对应条款**：决定日志字段集。
- **不要抄**：monday 工作区营销。

### B20 PM Stack Exchange — How should a PM capture decisions?

- **可用**：社区共识：决定与行动分列；会后 24h 内成文；未写入的口头承诺默认无效。
- **对应条款**：纪要「口头承诺：无/有则作废」。
- **不要抄**：个别高票轶事当标准。

### B21 ProjectManagerTemplate — Decision Logs guide

- **可用**：日志服务审计与移交；缺日志则换人后重开争论。
- **对应条款**：09 不另发明口径；决定可追溯到 08/05 纪要。
- **不要抄**：模板商城。

### B24 Plane 2026-02 — Decision log template

- **可用**：决定日志 ≠ 会议笔记/聊天；要可检索。所有人、备选、日期。支持治理与审计。
- **对应条款**：正式件进 `正式/现行/`，不进微信。
- **不要抄**：Plane CTA。

## 博客交叉后只留这几句

1. 矩阵先于信道：先 power/interest，再频率与深度。  
2. 高管包 ≠ 执行包。  
3. 每项决定一个 A；升级按阈值。  
4. 口头不算数，进日志才算数。  
5. 厂商统计数字一律不进合同。
