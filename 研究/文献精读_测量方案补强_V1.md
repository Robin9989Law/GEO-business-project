# 近三年测量文献精读 → 可落地补强

阅读日期：2026-08-16。范围：2023–2026。  
目的：对照现有手册，只吸收**能改采集/出数/验收**的协议，不扩写成又一篇综述。

现有雏形已对的：冻结词表、冷会话、多轮、App/API 分通道、别名表、Holdout、limited。  
文献要求补上的：轮次不够、没有置信区间、没有稳定性 KPI、提及≠吸收、没有 SOV/位置、没有「先测噪声再谈涨跌」。

## 2. 对照我们手册：缺什么

| 文献要求 | 手册现状 | 补强 |
|---|---|---|
| 品牌检测约 7 轮才 SE&lt;0.10 | App 正式 3 轮，API 3 轮 | **API 哨兵改 7 轮**；App 3 轮只作定向级，决策级用「3 轮 × 连续 7–10 天」或验收周加到 7 |
| 来源比品牌更抖，要 8 轮 | 有 source 字段，无来源稳定性 | 增加日际 Jaccard；来源结论不要用 1 天 3 轮 |
| 滚动 2–4 周 | 只有单日 P() | 增加 7/14/28 日滚动 P(提及) |
| Bootstrap CI，重叠不宣布胜出 | 只报点估计 | 出数加 95% CI；重叠写「无法区分」 |
| 先建变异基线 | 第 4 周才「测噪声」 | **干预前必须有无干预周的波动** |
| 选引 ≠ 吸收 | `source_owned` 只是来源是否自有 | 增加吸收代理：答案是否复述台账字段 / 指纹 |
| 不带品牌的发现问 | 词表已有，但没标 branded | `queries` 加 `branded` 列；主结论只用 unbranded |
| 六类问法 | 只有 intent/style | 映射到 discovery / problem / compare / use_case / expert / brand_research |
| 位置 / SOV | 只有 mention 0/1 和 recommend 0/1/2 | recommend 已接近 prominence；补 SOV 与竞品分母披露 |
| 情感极不稳定 | 未采 | **不要做主 KPI**；需要时单独、加宽 CI |
| 分引擎基线 | 已分平台 | 保持，禁止三 App 平均成一个数 |
| 问法异质性 | 已做乱问池 | 出数时按 style 分层，不把残句和完整句混成一条 |
| 同时重跑 vs 跨日 | 未区分 | 基线日：同日连跑 = 随机性；跨周 = 漂移。两边都要 |
| 采集架构披露 | App 金标准 + API 哨兵 | 对外写明：主动模拟，不是面板/平台原生 |
| 搜索是否触发 | 未记 | API 记 `search_triggered`；未联网的当另一通道 |
| 品牌词表质量 | 有 aliases | 若整场平均 mention 过低，先查词表漏检（Schulte 用 70% 检测率过滤场次） |

## 3. 建议立刻改的协议（按优先级）

### P1 轮次与窗口（Schulte）

- **API 日更：** 每条 core/holdout **7 次**独立请求（来源分析用 8）。  
- **App 金标准：** 人手不够时保持 3 轮，报告必须写「定向级，SE 约高于 0.10」。合同/复测周：同一冻结词表连续 7 天 × 每天 1 轮，或单日 7 轮（选人力能做的一种，不要混报）。  
- **滚动窗：** 监测看 14 日滚动 P(提及)，不看昨天一个点。  
- **稳定性 KPI：** 相邻两日（或同日两轮集合）品牌集合 Jaccard；来源集合 Jaccard 另表。Jaccard 低不是事故，是系统属性；用来判断「今天这点估计能不能信」。

### P2 不确定性（Sielinski）

对每个切片（平台 × 通道 × query_set）做响应级 bootstrap：

1. 有效行当作总体的一次抽样。  
2. 有放回抽 B=1000 次，每次重算 P(提及)、P(推荐)、SOV。  
3. 取 2.5% / 97.5% 分位为 95% CI。  
4. **两条 CI 重叠 → 禁止写「A 比 B 好」或「比基线提升了」。**

干预结论：处理组 Δ 的 CI 与 Holdout Δ 的 CI 必须错开，才允许勾「L1 有证据」。

### P3 指标分层（IAB 4P + Zhang + Ranqo）

| 层 | 我们怎么落地 | 不要做成 |
|---|---|---|
| Presence | 已有 mention；加 SOV=自己提及次数/(自己+合格竞品) | 三平台平均 SOV |
| Prominence | 已有 recommend 0/1/2；能抄名单则加 `position`（1,2,3,99） | 情感当位置 |
| Portrayal | accuracy + 同名排除；幻觉另记 | 把 sentiment 当主表 |
| Persuasion | recommend=2 作代理；咨询只观察 | 承诺 CTR |
| Selection | source_owned、search_triggered | 引得越多越好 |
| Absorption | 答案复述 confirmed 字段数、fingerprint 命中 | 有链接就等于被吸收 |

合格竞品：`aliases` 里 type=competitor 且本切片至少出现 2 次。一次幻觉店名不进分母（Ranqo）。

### P4 问法设计（Ranqo + Zhang + 已有乱问）

- 主验收只统计 `branded=0` 的 core。带品牌名的问法另表，测的是「点名后是否说对」，不是发现。  
- 把现有 intent 映射：locale/category→discovery 或 use_case；compare→comparison；qualify→expert/problem；risk→problem；groupchat 仍是 style。  
- Explore 乱问继续只打 API；出数按 style 分层，残句单独一行。  
- 扩写仍用 `08_问法扩写.md`，不得升 core。

### P5 实验时间线（IAB + Sielinski + 手册 Holdout）

```text
周 0     冻结词表、别名、竞品集合（书面披露）
周 1     变异基线：无干预，App 每天 1 轮或 3 轮×2 天 + API 7 轮/日
周 2     正式 baseline（记版本、城市、通道）
周 3+    干预（一轮一类证据）
等待 3–7 天
复测     同口径；处理组 vs holdout；CI 不重叠才下 L1
之后     14 日滚动监测；App/API 改版则重置基线
```

没有周 1 变异基线，不允许把周 2→复测的涨跌写成效果。

### P6 采集披露（IAB）

对外固定写四句：

1. 金标准是中国消费级 **手机 App 主动冷问**，不是面板、不是平台后台。  
2. 哨兵是官方联网 API，与 App 不是同一产品，数字分表。  
3. 问法来自冻结用户原话（含乱问），不是工具自动生成后未审核的词。  
4. 轮次、CI、limited、版本均公开。

### P7 不要从文献里抄错的

- 不要把厂商「30 次」写成最低门槛。  
- 不要把 MR 博客的「3 次」当成 Schulte 原文。  
- 不要把情感、FAQ 化、发文量当吸收。  
- 不要把跨平台来源重叠低当成测量失败（Ranqo/Yang：引擎之间本就低）。  
- 不要在 App 上追求论文里的 10 轮同日连打——人手会炸；用 API 承担高频，App 承担外部效度。

## 5. 一句话给负责人

文献把「测得准」从 3 轮点估计，抬成了：**足够轮次的分布 + 置信区间 + 滚动窗 + 选引/吸收分家 + 先测噪声**。  
我们的 App 金标准可以继续 3 轮（定向），但 **API 必须加到 7 轮，出数必须带 CI，复测必须先有无干预周。** 否则对外仍是故事。
