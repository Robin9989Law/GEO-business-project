# GEO 交付产品说明书

人第一次打开本目录，请按这个顺序读完再动手。不要先翻 `流程/` 里的九套表格，也不要先开发软件。

1. **第 1–3 章**：搜索怎么变了、市场上常见的错卖法、我们到底卖什么。读完应能向同事用自己的话复述「提及概率」和「为什么不能保证推荐」。
2. **第 4–6 章**：用一个虚构案子（叉车A / 示例市）把全部关键名词走通。读完应能区分有品牌问 / 无品牌问、提及 / 推荐、处理组 / 监测组、App 冷会话 / API、噪声 / 基线、四选一。
3. **第 7–9 章**：你和 Agent 怎么分工、材料放哪、**第一天从打开文件夹到批完 G0** 的具体动作，含可抄的交件样例。
4. **第 10 章**：诊断单从头到尾的故事（仍用叉车A），看清 01→09 为什么不能倒。
5. **第 11 章**：冲刺、续约和诊断差在哪。
6. **第 12 章**：九站速查。到了那一站再细看，不要第一天全填。
7. **第 13 章及以后**：命令、仓库分层、卡点、下一步该打开哪一份。

打开本文件夹即开工。把目录交给编排 Agent。你只做三件事：**交材料、审核草稿、在门上说批准 / 驳回 / 要改**。不要改 `state.json`。不要只做到交付（06）就宣布结案。

本页是给人看的产品说明书。Agent 的开工提示词是根目录 [AGENTS.md](AGENTS.md)。规格总线是 [合同/核心合同.md](合同/核心合同.md)。

## 1. 背景：用户已经不再「搜一页链接」

### 1.1 过去怎么被找到

过去一个人想在示例市考叉车证，会打开搜索引擎，打「示例市叉车证哪家靠谱」。屏幕上出现一页蓝色链接：官网、百科、问答、广告、地图。品牌可以靠这几件事抢位置：把官网写清楚、买关键词、做百科、在问答里露脸。用户通常会点开几个页面自己比。

那时候「有没有被看到」大致等于：搜索结果页上有没有你、排第几、广告位有没有占到。数字相对好解释，也相对好验收——截一张搜索结果页就能对。

### 1.2 现在怎么被找到

同一句话，现在很多人直接打进豆包、通义、DeepSeek、元宝这类消费级 AI App。模型用一段话回答，里面可能点名两三家机构，也可能只给办理步骤，一个品牌都不提。用户看完这段话，往往不会再点开十个链接核对。

于是出现一种新的「被看到」：

- 用户**没有说出你的品牌名**；
- 他只是在问「哪家正规」「在哪报名」「要什么材料」；
- 模型的回答里**有没有正确地提到你**。

提到了，你才进入候选。没提到，官网写得再好，这一轮发现路径上你等于不存在。点名了但是张冠李戴（同名机构、过期地址、错误电话），比没提到更糟。

GEO（Generative Engine Optimization）说的就是这件事：在生成式回答里，品牌有没有被**正确地提到**。它不是搜索引擎优化（SEO）换了个字母，也不是再买一轮关键词。优化对象从「结果页上的链接位置」变成了「模型会不会把你写进那段话」。

### 1.3 为什么这件事难验收

模型回答不是稳定的排行榜。

- 同一句问，同一天问两次，说法可能换。
- 登录态、城市定位、产品模式（标准搜还是深度搜）、是不是新建对话，都会改答案。
- 网页演示、开放 API、已经聊了二十轮的旧窗口，和用户在手机上**新建对话打一句口语**，不是同一次观察。
- 「被提到」不等于「被推荐」，更不等于「有人来咨询、来报名」。

所以，如果有人拍胸脯说「做完保证进前三」「报名会因此涨 30%」，他卖的不是可验收的观察，是无法兑现的增长故事。现有公开研究够支撑**怎么测、哪些话不能说、门禁怎么设**，不够支撑「行业标准等待 90 天」「提及率保证涨 20%」这类定额。本产品按这个边界卖，不发明定额。

### 1.4 市场上三种常见走偏

打开本目录之前，你很可能已经听过类似承诺。对照下面三条，能判断对方是在卖观察，还是在卖故事。

| 走偏 | 听起来像 | 实际问题 |
|---|---|---|
| 通道偷换 | 「我们用接口跑了 1 万次，可见性 42%」 | 用户看见的是手机 App 冷会话。网页和开放 API 可以做同日哨兵，不能代替用户所见。 |
| 终点偷换 | 「被推荐了」「咨询涨了」「报名涨了」 | 合同能锁死的主终点，只有无品牌发现问上的**正确提及**。推荐只观察。咨询和报名受广告、地推、季节、销售话术影响，不能当 GEO 验收。 |
| 口径偷换 | 「国内主流平均可见性」 | 漏测约定的任何一家 App，覆盖就不完整。几家数字加起来再平均，会掩盖「通义有、DeepSeek 没有」。禁止七家平均，禁止把漏测说成已覆盖。 |

还有两类更隐蔽的偷换：

- **未冻先比**：词表还在改，就把这周数字和上周比。比的不是同一批问。
- **未噪声先解释**：同一句问本身就会晃，却把「高了两个点」讲成优化成功。

本产品把这些全部写成硬规则。销售说漏了，范围卡作废，要从洽谈重开。

## 2. 我们到底卖什么

### 2.1 一句话

在用户会打的**无品牌原话**上，提高品牌在国内消费级 AI App 里被**正确提及**的概率，并用冻结词表上的分布说明：这种变化目前只够描述，还是（极少数冲刺）够得上受控对比。

拆开听：

- **无品牌原话**：用户没提你的名字。例如「示例市叉车证哪家正规」，不是「叉车A 靠谱吗」。
- **国内消费级 AI App**：豆包、通义、DeepSeek、元宝这类手机应用。不是网页演示，不是开放 API。
- **正确提及**：回答里出现的是对的那家，不是同名机构或过期事实。
- **概率**：在冻结词表、约定平台、约定轮次上的分布，不是「全市用户总体」，也不是保证下一次一定提到。
- **描述还是对比**：默认只能描述「现在长什么样」或「动过之后两边各长什么样」。确认某次改页「导致」提及变化，是极严的例外，不是标配。

### 2.2 不是什么

| 不是 | 为什么 |
|---|---|
| 投放后台 / 买词代运营 | 我们不替客户烧广告预算，也不接管销售线索。 |
| 改页工厂 | 诊断单明确不改页。冲刺最多一轮一类证据（例如只改 FAQ），不是把官网、列表、视频一起翻新。 |
| 「保证会被推荐」的增长套餐 | 推荐和报名都不是主终点，也不能保证。 |
| 新软件、新 App、新后台 | 本目录本身就是交付系统。不要再开发一套。 |
| 行业对标排名 | 不卖「你们在全国排第几」，只卖约定品类、约定城市、约定 App、约定问法上的观察。 |

### 2.3 一张表看清边界

| 问 | 答 |
|---|---|
| 卖什么 | 诊断 / 冲刺 / 续约，一单只选一条 |
| 解决什么 | 指定品类 + 指定城市里，「没提品牌名的发现问」上提不提得到你 |
| 主终点 | 只有提及概率 `p_mention`。咨询、报名只观察，不当合同主终点 |
| 能说到哪 | 四种结论里的一种，见第 6 章。默认是描述，不是因果保证 |
| 怎么观察 | 手机 App **新建对话**是金标准；API 只做同日哨兵 |
| 怎么收口 | 01→09 全流程 + 文件库。交付完还要结项 |
| 数字认谁 | 只认 `流程/03 测量` 手册和出数脚本。周报、结项、口头都不能另发明口径 |

### 2.4 谁适合、谁不该买

**适合**

- 本地培训、本地生活、本地服务：用户会用口语问「哪家靠谱」，而不是只搜品牌名。
- 能拿出真机、干净号，并把定位切到合同城市。没有真机、只能跑网页的，测不到用户所见。
- 接受「先测现在长什么样，再决定改不改」。不知道自己在不在回答里，应先买诊断，不要一上来改全站。
- 接受每一道门由人签字，Agent 不能代批。这是交付纪律，不是客服话术。

**不适合（听到这些应停在洽谈，不要立项）**

- 「你能保证我们会被推荐进前三。」
- 「做完报名会涨。」
- 「用网页 / API 数字交差就行，别让销售去冷问。」
- 「诊断也顺便把官网和 FAQ 改了。」
- 「把七八个 App 平均一下，对外说全国可见性。」
- 「先测着，测到一半再升级成冲刺。」——诊断不能在需求阶段加宽成冲刺，要重开范围。

销售与售前禁句全文：[流程/01 客户初次洽谈/禁售清单.md](流程/01%20客户初次洽谈/禁售清单.md)。人确认已读后，字段 `ban_ack` 才能是「是」。客户原话里若带禁售句，进隔离区，不能当正式件。

## 3. 三条产品线

01 洽谈只提**意向**，02 需求才把产品线锁死。锁定后只能收窄，不能加宽：诊断不能在 02 升成冲刺。一张合同只许一条线。

### 3.1 三条分别买到什么

| 产品线 | 客户真正买到的 | 明确不包含 | 结束后允许说的话 |
|---|---|---|---|
| **诊断** | 冻结词表，采噪声和基线，描述各约定 App **现在**怎么提及你 | 改页、发文、干预、确认性因果 | 「描述基线」或「不能下结论」 |
| **冲刺** | 诊断那些事 + **一轮一类**证据（例如只改 FAQ）+ 等待 + 复测 | 监测组页面被改；默认卖「已经证明有效」 | 默认「受控前后描述」。确认性 L1 极严，见第 6 章 |
| **续约** | 按周监测和校准，看有没有滚动异常 | 新开处理组、用周报重开因果 | 「不能下结论」（异常只观察） |

口语对照，帮销售和客户选线：

- 「我们根本不知道 AI 里有没有我们」→ **诊断**。
- 「知道基线了，这一轮只改一类内容，想看前后差」→ **冲刺**。必须已经有一次诊断（或等价的冻结基线），并且接受「只改一类」。
- 「内容暂时不动，只要按周盯着别掉下去」→ **续约**。
- 「诊断做到一半升级成冲刺」→ **不行**。要重开范围，不能在 02 加宽。

### 3.2 确认性 L1 不是第四条产品线

市场上常把「我们能证明 GEO 有效」单独卖成一档。本产品不这么卖。

**确认性 L1** 是冲刺复测后极少达到的门：隔离设计已成立、主终点对比的区间不含 0、覆盖和簇数达标。章程阶段（02）不能预先写成「我们做隔离因果」。报价里不能把 L1 当成标配（字段必须是 `quote_excludes_l1=是`）。对外说话不能宽于本案实际写出的那一种四选一。

一句话：**L1 是冲刺做完之后够不够格的结论，不是开单时能卖的套餐。**

### 3.3 为什么诊断不能中途升冲刺

诊断的预算不含改页，沟通口径不能预告「优化后会涨」，测量计划里没有干预窗。如果测到一半说「顺便改 FAQ」，等于：

- 用诊断的钱做冲刺的活；
- 监测组可能已经被改，对照作废；
- 对外已经用诊断口径讲过话，再改口就是加码。

所以规则写成硬的：要冲刺，另开范围，从 01/02 重新锁。不要在同一张诊断合同上加一行「也改页」。

## 4. 用一个虚构例子把名词讲清楚

下面用虚构代号 `叉车A`、城市「示例市」、品类「叉车证培训」。这是说明书里的教具，**不要**抄进通用模板当真实客户，也不要把真实客户全称写进 `流程/` 或 `合同/` 下的模板原件。

假设：示例市有好几家叉车证培训。叉车A 是其中一家。老板听说「现在年轻人都问豆包」，想知道豆包会不会提到他们。

### 4.1 有品牌问 vs 无品牌问

| 用户打的字 | 类型 | 说明什么 | 主终点看吗 |
|---|---|---|---|
| 「叉车A 培训靠谱吗？」 | 有品牌问 | 用户已经想到你，模型在评价你 | **不看** |
| 「示例市叉车证哪家正规？」 | 无品牌发现问 | 用户在找选项，还不知道你 | **看** |
| 「叉车证报名要带什么材料？」 | 无品牌、偏流程 | 用户在办手续；若本轮不优化这类问，可进监测组 | 看，但是否进处理组由 02 锁 |

如果报告里大量混进有品牌问，提及率会被抬高——模型本来就知道你的名字。那张表回答不了「发现问上有没有你」。合同主终点只认无品牌发现问。

### 4.2 提及 vs 推荐 vs 报名

模型回答里出现「叉车A」，且指的是对的那家（不是另一家同名机构），叫**提及**。主终点字段名是 `p_mention`。

进一步说「建议去叉车A」或「首选叉车A」，叫**推荐**。字段名是 `p_recommend`，只观察，不当合同主终点。

用户有没有去咨询、报名，叫业务结果。受广告、地推、价格、销售话术、季节影响。本产品**不当合同主终点**。可以对客户说：「报名我们只观察，不写进验收。」

三者经常被捆在一起卖。拆开的原因很具体：模型提了你，用户未必点；点了未必咨询；咨询了未必报名。GEO 能锁死的，是第一环。

### 4.3 为什么必须用手机 App 冷会话

用户真实路径是：打开豆包 / 通义 / DeepSeek / 元宝，**新建对话**，打一句口语。下面这些东西都会改答案，所以必须写进环境登记，不能省略：

- 是不是干净号（旧对话、收藏、记忆功能会污染）；
- 定位有没有切到示例市（切到别的城市，模型可能推当地另一家）；
- 当天用的是标准搜还是深度搜（同一天只许一种产品模式）；
- 是不是新建对话（旧窗口里追问，等于换了一次试验）。

网页演示、开放 API、已经聊了二十轮的旧窗口，都**不能**代替这次冷问。API 可以同一天跑一遍，用来发现异常（例如某家接口突然空答），报告里必须和 App **分表**，不能写「API 也是用户所见」。

一次合格冷问大概是：

1. 干净号，定位切到示例市；
2. 当天只选一种产品模式；
3. 点新建对话；
4. 只打合同里的那一句原话，不补「请联网」、不润色、不追问；
5. 保存全文和截图。

细则在 [流程/03 测量/README.md](流程/03%20测量/README.md) 和操作手册。不要让 Agent 自动点消费级手机 App。

### 4.4 默认要测哪几家

最小档（P0，必测）是四家 App：豆包、通义、DeepSeek、元宝。Kimi / 文小言 / 清言默认不测。不要只采三家还写「已覆盖国内主流」——DeepSeek 是必测。

每一家单独出数。禁止把四家数字加成一个「平均可见性」对外讲。漏测任何一家约定 App，覆盖就不完整，验收可以拒收。

### 4.5 处理组 vs 监测组

信息需求（need）是「用户想搞清楚的那一类事」，不是某一句具体问法。一句问法从属于一个 need。

叉车A 这一单可以这样切：

| 组 | need 例子 | 对应问法例子 | 这一轮做什么 |
|---|---|---|---|
| 处理组 `treat_need_ids` | 「在哪报名」「哪家正规」 | 「示例市叉车证哪家正规」 | 冲刺时只动这些问法对应的内容 |
| 监测组 `holdout_need_ids` | 「要什么材料」「多少钱」 | 「考叉车证要带什么材料」 | **故意不改**相关页，用来对照 |

两组 need **不能相交**。同一条问法不能既处理又监测。

监测组不是「假如我们没做会怎样」的反事实实验室。它只是同品类同城、本轮未优化的比较对象。冲刺时如果改了监测组对应页面，对照就废了，最终四选一只能落到「不能下结论」。

诊断单也要锁监测组：不是为了改页对照，而是为了出数时分表，避免只报处理组、把好讲的问法挑出来。

### 4.6 为什么先采噪声，再谈涨跌

同一句「示例市叉车证哪家正规」，同一天在豆包问两次，模型也可能换说法：一次提叉车A，一次只提流程。这种晃动叫**噪声底**。它不是效果，是测量对象自己的不稳定。

没有噪声底，就把「这周比上周高两个点」讲成优化成功，属于禁售。诊断至少要有噪声 + 基线；没有噪声，任何涨跌都只能停在「不能下结论」。

默认最小档的节奏（细节以测量手册为准）：

- **噪声**：干预前连续若干天，每天一轮 App，用来估计晃动；
- **基线**：噪声周之后，按约定轮次采，用来描述「现在长什么样」；
- **复测**：仅冲刺，改完并等满等待天数之后，用同一张冻结词表再采。

### 4.7 冻结是什么

测量前把问法、别名、事实、自有来源、平台名单锁进本案的冻结目录，得到一个 `freeze_id` 和校验和。之后采集、出数、对比都认这一版。

可以把它想成「拍照时按下快门」：快门之后再改镜头，那张照片就不能和新镜头比。中途改 need 或平台，必须新冻结，不能拿旧数和新词表比。

未冻结就去冷问，数字作废。未冻结就对比，属于禁售。

### 4.8 一类证据是什么（冲刺才有）

冲刺允许动内容，但一轮只许一类。例如这一轮只改 FAQ，就不要同时改列表页、同时发视频、同时改百科。混在一起，复测时说不清是哪一类起的作用。

「一类」写在干预轮次卡上，完成日也写上。等待天数至少 1 天，且完成日 + 等待天数必须已经到「今天」，才能写最终四选一。昨天刚改完、今天就出「受控前后描述」，时钟不算满。

## 5. 为什么顺序是 01→02→07→08→03，而不是先测

文件夹上印着 01、02、03……那是标签，**不是**走路顺序。真正的顺序是：

```text
01 洽谈 → 02 需求 → 07 预算 → 08 沟通 → 03 测量 → 04 计划 → 05 实施 → 06 交付 → 09 收尾
```

07 预算和 08 沟通在测量**之前**。09 收尾在交付接收**之后**。G4（客户接收报告）通过不是结案。

为什么不能立项第二天就去冷问？

| 若跳过 | 会坏什么 |
|---|---|
| 跳过 01 禁售 | 客户原话里的「保证推荐」会进正式件，后面所有报告都在兑无法兑现的承诺 |
| 跳过 02 锁 need / 平台 | 操作员按自己的理解问，词表和验收对不上 |
| 跳过 07 | 按冲刺的活收诊断的钱，或把 L1 写进报价 |
| 跳过 08 | 出数后老板看到 API 表，对外说成「已经优化成功」 |
| 跳过冻结（03 第 0 天） | 采了也无法对比 |
| 诊断单在 04/05 排改页 | 产品线被偷换成冲刺 |
| 只做到 06 | 中转没清、资产没脱敏、教训没沉淀，客户事实可能泄漏进资产库 |

人的直觉是「先测一测再谈钱」。本产品反过来：先锁范围、钱、对外能说的话，再按锁死的词表去测。测的成本由 07 估过；测完能说的话由 08 锁过。这样销售、测量、客户成功不会各讲各的。

## 6. 对外只能落在四种结论里

这就是「四选一」。数字从哪来、谁有权写，只认测量手册和出数脚本。周报、验收单、结项、口头汇报，只能抄已经写出的那一种，不能加码。

| 结论 | 什么时候可以写 | 人话 | 绝不能顺嘴加成 |
|---|---|---|---|
| 描述基线 | 诊断（以及冲刺的基线阶段） | 约定 App、约定问法上，现在提及长这样 | 「所以已经有效」 |
| 受控前后描述 | 冲刺复测后的默认 | 处理组动过、监测组没动，前后分布可以这样描述 | 「已证明 GEO 有效」「报名会涨」 |
| 确认性 L1 | 仅冲刺，且隔离 + 对比区间不含 0 + 覆盖和簇数达标 | 在本案设计下，主终点的对比排除了零 | 「保证下次还这样」「全市用户都会看到」 |
| 不能下结论 | 噪声不够、覆盖不全、续约、或证据达不到上三档 | 这份数据支撑不了更强的话 | 用「方向是好的」偷偷升级 |

谁写最终四选一：

- 诊断、续约：在 **03 测量**写完。
- 冲刺：03 只写基线四选一；**05 复测且等待期满**后才写最终值。
- 06 交付只抄已经锁住的值，09 结项再回声一次，都不能加码。

冲刺的等待不是填个数字就行：完成日 + 等待天数必须已经到「今天」，`wait_days` 至少为 1，才能写最终四选一。

02 章程里还有一个配套字段 `causal_claim`。开单时必须锁成「描述到隔离为止」（`descriptive_until_isolation`）。只有冲刺在 05 真正达到确认性 L1 之后，才能改写成隔离对比（`did_isolated`）。不要在章程里预先写成后者。

## 7. 你和 Agent 怎么分工

### 7.1 总原则

编排 Agent 读根目录 [AGENTS.md](AGENTS.md)，带着人把 01→09 做完。人不要自己翻完整模板堆，问 Agent「现在先做什么」。

标准回合永远是这一圈，不是把九站表格一次性甩过来：

```text
Agent 讲清本站 → 你按路径交材料 → Agent 质检
  → 不合格则打回（硬规则不能申诉）
  → 合格则起草正式件 → 停在门上等你拍板 → 下一站
```

### 7.2 谁做什么

| | 你 | Agent |
|---|---|---|
| 材料 | 原话、禁售回执、冷问全文和截图、接收/拒收 | 入库、质检、起草正式件、过门后发正式版 |
| 决策 | 批准 / 驳回 / 要改 | 判断走到哪、卡住禁售和硬规则 |
| 状态文件 | **不要改** `state.json` | 只通过引擎写 |
| 数字和四选一 | 审报告，不改口径 | 只引用 03 出数 |
| 签字 | 只有人可以批准 | Agent 不能 `APPROVE`，也不能覆盖硬规则 |
| 消费级 App | 人在真机上新建对话、打原话 | 禁止自动点手机 App |

### 7.3 开单先报三个熟练度

用**成员代号**，不要用真名。三个轴各选 0 / 1 / 2：

| 轴 | 0 | 1 | 2 |
|---|---|---|---|
| `pm_level` 项目管理 | 没做过项目 | 跟过项目 | 能独立收口 |
| `geo_level` GEO | 没接触过 | 听过口径 | 能读出数、能解释四选一 |
| `tool_level` 文件和命令 | 不会放文件 | 能按路径放 | 能自己跑命令 |

讲解深度按这三轴变：生疏的那一轴会讲概念和例子，熟练的那一轴只给差异。路径、门、禁令**不会**因为你熟就藏起来。系统**不会**因为两次顺利提交就自动把你升档，升级要人显式确认。

### 7.4 门上只说三句

| 你说 | 意思 | 之后 |
|---|---|---|
| **批准** | 本站正式件可以发布，进入下一站 | Agent 把 `out/` 升到 `正式/现行/` |
| **驳回** | 本站不能过，留在本站改 | 不升正式版 |
| **要改（CHANGE）** | 退回某一站重做 | 必须说明退回哪一站、影响哪些字段和正式件 |

CHANGE 不是口头改一句范围。例如冲刺做到一半要把监测组的 FAQ 也改了，必须走 CHANGE，不能在周报里改口。

### 7.5 哪些门必须两个人签

关键门必须**两名不同成员**、两个规定角色都签，并写原因：

| 门 | 站 | 两个角色 |
|---|---|---|
| G1 | 02 需求 | 负责人 + GEO/验收专业复核 |
| G3 | 03 测量 | 负责人 + 测量复核 |
| G4 | 06 交付 | 负责人或客户成功 + 测量复核 |
| G8 | 09 收尾 | 负责人 + 文件/资产复核 |

G0 / G6 / G7 / G2 / G5 可以单人，仍建议写下是谁、什么角色、为什么批。同一个人签两个角色不算双签。角色对照：[合同/关键门双角色表.md](合同/关键门双角色表.md)。

完整的门链：

```text
01 --G0--> 02 --G1--> 07 --G6--> 08 --G7--> 03 --G3--> 04 --G2--> 05 --G5--> 06 --G4--> 09 --G8-->
```

## 9. 第一天具体怎么做

下面假设还没有任何真实案件。仓库里可能有教学用的合成案件，那不是你的单，不要往里面填真客户。

没有命令行也能做完本章。把文件丢到 inbox 或聊天里，让 Agent 入库即可。命令是加速项，见第 13 章。

### 9.1 第 1 步 · 打开目录

把本仓库交给编排 Agent（Cursor / Grok / 终端里打开本文件夹均可）。不要先开发新软件，不要先改引擎。

### 9.2 第 2 步 · 听 Agent 的四句话

合格的开场一定包含这四件，缺一句就让它补：

1. **现在在哪**：没有案件就是 01 洽谈。
2. **先做什么**：读禁售、交四字段和原话。不是去冷问。
3. **你要交什么**。
4. **放到哪条路径**。

如果 Agent 一上来甩 01–09 全部表格，或问「要不要开始」，让它按 [AGENTS.md](AGENTS.md) 重说。

### 9.3 第 3 步 · 答三个 level

例如：「项目管理 1，GEO 0，文件 1。我的代号用 `owner_a`。」

Agent 会按代号写入档案。不要用真名。

### 9.4 第 4 步 · 读禁售并回执

打开 [流程/01 客户初次洽谈/禁售清单.md](流程/01%20客户初次洽谈/禁售清单.md)，通读。然后交一份回执。可以放在：

```text
agent_pm/cases/叉车A/inbox/01_禁售已读.txt
```

内容只要写清楚「谁、哪一天、确认已读禁售清单，本案不使用清单上的句子」即可。例如：

```text
成员代号：owner_a
日期：2026-08-16
确认：已阅读《禁售清单》，本案对外与对内均不使用清单上的句子。
ban_ack：是
```

这是 G0 的硬条件。没这份回执，不能立项。

### 9.5 第 5 步 · 交四件洽谈材料

可用口语，Agent 负责入库。建议写成一个文件，放在：

```text
agent_pm/cases/叉车A/inbox/01_客户原话.md
```

可抄结构（数字和店名都是教具）：

```text
# 叉车A · 01 洽谈材料

- 品类口头说法：叉车证培训
- 目标城市：示例市
- 内部代号：叉车A
- 意向产品线：诊断
- 决策人代号：客户侧-校长
- 对接代号：客户侧-教务

## 客户原话

「我们想知道豆包、通义这些里面，学员问哪家正规的时候会不会提到我们。
先不要改官网。先看现在到底有没有我们。」

## 禁售核对

- 客户是否要求保证推荐或报名增长：否
- 若原话曾出现「保证进前三」：已改口为「无品牌发现问上的提及概率」，原句进隔离，不进正式件
```

四件缺一不可：品类、城市、代号、意向产品线。再加原话。原话进原始库。若原话带「保证推荐」，进隔离，先改口到提及概率，否则不立项。

### 9.6 第 6 步 · 等人起草商机卡，你只审

Agent 会起草商机卡和范围边界。你审三问：

1. 是不是只选了一条产品线？
2. 原话有没有进档案（而不是只留在聊天里）？
3. 保证推荐有没有改口？禁售回执是不是「是」？

然后批 G0，或驳回，或 CHANGE。你不能让 Agent 代批。

### 9.7 第 7 步 · 不要跳

G0 之后是 02 需求，然后是 07 预算、08 沟通，**才**到 03 测量。不要一立项就让操作员去冷问——词表还没锁，预算和对外口径也还没锁。

第一天到这里就可以停。需求材料可以第二天再交。

## 10. 诊断单从头到尾长什么样（仍用叉车A）

下面是教学走法，不是定额，也不是排期承诺。目的是让你看见每一站「交什么、得到什么、为什么还不能测 / 还不能结案」。

### 10.1 01 洽谈：接不接、接哪条线

- 你交：第 9 章那四字段 + 原话 + 禁售回执。
- 你得到：商机卡。还不是章程，产品线此时只是意向。
- 你拍板：G0。
- 停在这里的原因：客户如果坚持「保证推荐」，后面所有站都会被迫兑假承诺。

### 10.2 02 需求：锁成验收合同

你补两样：

1. **信息需求清单**：处理组有哪些 need，监测组有哪些 need，各举两句用户会打的原话。
2. **怎样算提到了叉车A**：别名（例如口语简称）、必须排除的同名机构、已确认的地址和电话。

Agent 起草章程、需求规格、验收标准。你确认：

- 主终点只能是提及概率，不能写成报名；
- 处理组和监测组不相交；
- 因果主张此时必须是「描述到隔离为止」；
- 三套验收规则都写上（诊断 / 冲刺 / 续约各一套），且和选中的产品线一致——诊断单的成功规则只能是「描述基线」或「不能下结论」。

G1 必须两个人签：负责人 + GEO/验收复核。签完产品线从意向变成锁定，不能再升成冲刺。

### 10.3 07 预算：先锁人时，再谈采集

还不能去采 App。先按「激活问法 × 约定平台 × 本产品线允许轮次 × 角色」估人时。

单位：1 人时 = 1 人 × 1 小时；1 人天 = 8 人时。不要把「人天」和「人时」混写。不要抄别的品类的历史天数当定额。单次冷问未现场标定前，计划假设写在预算备注里，标明「假设未标定」。

诊断预算只许覆盖：冻结、噪声、基线、抽检、收尾。出现「改 FAQ」「一类证据」「干预」就是错的。报价必须书面排除确认性 L1。

你交：能出勤的操作员 / 评分 / 编排各多少人时。不要把客户成交价写进通用模板。

G6 批准后，后面的计划人时不能超过这个数。

### 10.4 08 沟通：先锁谁听什么

还是不能采。先登记：

- 决策人（只收四选一，不看 API 主表）；
- 对接（收周报和问题清单）；
- 内部负责人（收全套）。

对外口径必须写死「不得宽于四选一」。诊断阶段只能说「现在长什么样 / 不能下结论」，不能预告「优化后会涨」。附件顺序永远是：App 主表 → 监测组 → API 附表。

G7 批准后，采集开始就不能再临时发明口径。

### 10.5 03 测量：验收真相在这里产生

顺序不能倒：

1. 把 02 锁死的字段灌进配置，跑冻结，得到 `freeze_id`。
2. 环境登记：机型、系统、App 版本、定位城市、产品模式。
3. 按清单冷问。文件进 `流程/03 测量/案件/叉车A/样本/`。
4. 基线处理组必须第二人抽检。
5. Agent 跑 API 哨兵和出数。诊断的最终四选一在这一站写完，只能是「描述基线」或「不能下结论」。

未冻结不准采。没有噪声不准解释涨跌。App 表和 API 表必须分开。

G3 必须两个人签：负责人 + 测量复核。

### 10.6 04 计划：只排已经允许的窗

诊断只许三个窗：第 0 天（冻结和环境）、噪声、基线。进度里的人时必须大于 0，且不超过 07 已批预算。出现「改页周」「干预」「复测」就是把诊断偷换成冲刺。

G2 单签即可。

### 10.7 05 实施：诊断在这里不改页

诊断单本站没有干预轮次卡。周报只监测，四选一必须和 03 写出的相同。G5 对诊断是「不适用」，但你要知道：本步没有改页、没有发文。

如果有人在这一站「顺手改了 FAQ」，对照和产品线同时作废，必须 CHANGE 回 02 重开，不能假装还是诊断。

### 10.8 06 交付：收的是本案出数目录里的报告

交付物就是：

```text
流程/03 测量/案件/叉车A/出数/
```

里面的报告、覆盖表、日表、证据清单。共享的 `流程/03 测量/出数/` 是模板和演示，不能当交付。

你拍板：接收 / 拒收 / 补件。拒收要指出是覆盖不全、口径被放宽，还是材料对不上冻结。四选一这里不得改口。

G4 必须两个人签。签完**还不是结案**。

### 10.9 09 收尾：对照章程关门

对照 02 章程勾完成项。清空中转。脱敏沉淀：资产库只留可迁移结构（例如「FAQ 这一类证据怎么记账」），不留客户电话、点名问、未脱敏截图。禁止用结项报告重开 L1，禁止把诊断写成「有效果」。

G8 必须两个人签。这才是全流程结束。

## 11. 如果买的是冲刺或续约

### 11.1 冲刺比诊断多出来的

02 仍然不能预先写确认性因果。07 可以多报一类证据、等待、复测，但 L1 仍不进报价。08 对外默认只能预告「受控前后描述」，不能预告 L1。

03 只做冻结、噪声、基线，只写**基线**四选一，不做复测。

04 可以排干预窗、等待窗、复测窗。

05 才是冲刺的核心：

- 一轮只勾一类证据；
- 只动处理组；
- 监测组页面必须未改；
- 写下完成日，等到等待期满（至少 1 天，且完成日 + 等待天数 ≤ 今天）；
- 用同一冻结复测；
- **这时才写最终四选一**，默认「受控前后描述」。

只有隔离设计成立且主终点对比排除零时，才能写确认性 L1，并把 `causal_claim` 升为隔离对比。这是例外。

### 11.2 续约比诊断少掉的

续约不新开处理组，不改页，不用周报重开因果。03 跑第 0 天、按周监测、校准。最终四选一只能是「不能下结论」。滚动异常是观察，不是效果声明。

## 12. 九站速查（人要交什么、拍板什么、别踩什么）

编号是文件夹标签。**必须按表中的顺序走。** 07、08 在 03 之前。06 之后一定有 09。到了哪一站，只打开那一站的 `AGENT.md`，不要把九站表格一起填。

### 01 洽谈 · 门 G0

- **这一站为什么在**：先判断接不接、接哪条线，避免一上来承诺效果。
- **你交**：品类、城市、代号、意向产品线、客户原话、禁售已读。
- **你得到**：商机要点（还不是锁定的章程）。
- **你拍板**：接 / 不接 / 改口后再议。
- **典型错误**：诊断现场顺手卖冲刺；原话里的「保证推荐」没进隔离。

### 02 需求 · 门 G1（双签：负责人 + GEO/验收复核）

- **为什么在**：把意向锁成验收合同。主终点、need、平台在这里一次性锁死。
- **你交**：信息需求清单、竞品「怎样算提到了你」。
- **你确认**：`primary_endpoint` 只能是提及概率；处理组和监测组不相交；因果主张此时必须是「描述到隔离为止」。三套验收规则都要写上，且和选中的产品线一致。
- **典型错误**：主终点写成报名；处理组和监测组共用同一批问法；章程里先写隔离因果。

### 07 预算 · 门 G6

- **为什么在**：测量前先锁人时和报价范围，避免按冲刺的活收诊断的钱，或把 L1 卖进报价。
- **单位**：人时。1 人时 = 1 人 × 1 小时。
- **你确认**：人时按「激活问法 × 约定平台 × 本产品线允许轮次」估；`quote_excludes_l1=是`；诊断预算里没有干预 / 改页 / 一类证据。
- **典型错误**：诊断报价里出现「改 FAQ」「一类证据」；用故事点或他行业上浮当定额。

### 08 沟通 · 门 G7

- **为什么在**：谁听什么、对外能说到哪，必须先于出数锁死。
- **你交**：决策人、节奏、对外口径。
- **你确认**：决策人看四选一，不以 API 为主表；口径不得宽于 03 将写出的允许集。
- **典型错误**：周报里对老板说「已经优化成功」，比验收允许的话更满。

### 03 测量 · 门 G3（双签：负责人 + 测量复核）

- **为什么在**：验收真相在这里产生。
- **诊断 / 续约**：本步写最终四选一。
- **冲刺**：本步只写基线四选一，**不做复测**。
- **你做**：真机、干净号、定位到合同城市；按清单新建对话、一句原话、截图+全文。不要让 Agent 自动点消费级 App。
- **典型错误**：未冻结就采；把 API 表和 App 表合成一张对外讲；冲刺在 03 写「受控前后描述」。

### 04 计划 · 门 G2

- **为什么在**：只排已经允许的窗，不是愿望清单。
- **诊断只许**：`day0`（冻结和环境）、`noise`、`baseline`。
- **冲刺加上**：`intervention`、`wait`、`retest`。
- **续约**：`day0`、`weekly`、`calib`。
- **你确认**：进度里的人时 > 0 且不超过 07；诊断计划里没有干预窗。
- **典型错误**：诊断排了改页周；人时超过已批预算。

### 05 实施 · 门 G5

- **诊断**：不改页、不发文，周报只监测。G5 对诊断是「不适用」，但你要知道本步没有干预。
- **冲刺**：一轮只勾一类证据；只动处理组；监测组页面必须未改；写下完成日；等到等待期满再复测；**这时才写最终四选一**。
- **典型错误**：同时改 FAQ、列表和视频还当一轮；等待天数填 0 或完成日是昨天却写最终结论；周报口径比测量更满。

### 06 交付 · 门 G4（双签：负责人或客户成功 + 测量复核）

- **交付物**就是本案出数目录里的报告，不是另做一张可见性表。
- **路径**：`流程/03 测量/案件/{本案}/出数/`。共享的 `流程/03 测量/出数/` 不能当交付。
- **你拍板**：接收 / 拒收 / 补件。拒收要指出是覆盖、口径还是材料。
- **四选一**：诊断/续约抄 03，冲刺抄 05，这里不得改口。
- **典型错误**：收一份 API 主表；口头说「差不多」但校验和对不上。

### 09 收尾 · 门 G8（双签：负责人 + 文件/资产复核）

- **G4 通过不是结案。** 对照章程结项，清空中转，脱敏沉淀。
- **禁止**用结项报告重开 L1，禁止把客户事实写进资产库。
- **典型错误**：教训里写客户电话和点名问；结项把诊断写成「有效果」。

全程并行的 [流程/10 项目文件](流程/10%20项目文件/AGENT.md) 不是第 10 站，是档案室。

## 13. 命令（可选，不是开工前提）

没有命令也可以按路径交文件。有命令时，在仓库根目录操作。把 `叉车A` 换成本案代号。

```bash
# 开单（建案件库和档案室）
python3 agent_pm/run.py init 叉车A

# 看「现在在哪、先做什么、材料放哪」（给人看）
python3 agent_pm/run.py guide 叉车A

# 写入成员熟练度（profile.json 里是三个 level 和成员代号）
python3 agent_pm/run.py profile 叉车A --member 负责人 --json profile.json

# 人把 inbox 材料入库到原始库
python3 agent_pm/run.py deposit 叉车A --src agent_pm/cases/叉车A/inbox/01_客户原话.md --stage 01 --title 客户原话

# Agent 起草后由人批准。关键门必须两个不同成员
python3 agent_pm/run.py decide 叉车A --gate G0 --verdict APPROVE --actor human \
  --member owner_a --role 负责人 --decision-reason "禁售已读，意向诊断"

python3 agent_pm/run.py decide 叉车A --gate G1 --verdict APPROVE --actor human \
  --member owner_a --role 负责人 --decision-reason "章程字段已锁"

python3 agent_pm/run.py decide 叉车A --gate G1 --verdict APPROVE --actor human \
  --member owner_b --role GEO/验收专业复核 --decision-reason "三套规则与产品线一致"
```

CHANGE 必须带影响分析文件，不能只改口：

```bash
python3 agent_pm/run.py decide 叉车A --gate G5 --verdict CHANGE --actor human \
  --member owner_a --role 负责人 --rewind 04 --change-json change.json
```

`change.json` 至少含：原因、影响哪些字段、影响哪些正式件、作废哪些证据。

不要自己跑 `apply` 冒充 Agent 写字段。不要手改 `agent_pm/cases/叉车A/state.json`。

自检：`python3 check_pm_system.py`。状态机说明：[agent_pm/README.md](agent_pm/README.md)。人怎么被带着走：[agent_pm/agents/HUMAN.md](agent_pm/agents/HUMAN.md)。

## 15. 人话术语（对外优先说完整名称）

| 你可能听到的 | 人话 | 对外怎么说 |
|---|---|---|
| `p_mention` | 无品牌发现问上，有没有被正确提到 | 「提及概率」，不要说成「推荐率」 |
| `p_recommend` | 有没有被建议去这家 | 「推荐只观察，不是验收」 |
| App 可见性 | 用户在手机新建对话里实际看到的 | 「用户所见」，金标准 |
| API 哨兵 | 同一天用接口跑的对照 | 「不是用户所见，附表」 |
| 监测组 | 本轮故意不优化的比较问 | 「对照问，不是假如没做会怎样」 |
| 噪声底 | 同一问自己就会晃 | 「自然波动，不是效果」 |
| 冻结 | 词表和平台的快门 | 「这一版词表锁死后再采」 |
| 四选一 | 四种允许结论 | 只说其中已写出的那一种 |
| 受控前后描述 | 冲刺默认结果 | 「可以描述两边，不是已证明有效」 |
| 确认性 L1 | 冲刺里极严的那一档结论 | 不到门不要提；到了也不是报名增长 |
| 人时 | 1 人做 1 小时 | 不要和「人天」混用；1 人天 = 8 人时 |
| 项目账 | 只服务这一单的文件和数字 | 结项后封存 |
| 资产账 | 脱敏后可迁移的结构 | 不进客户事实 |

完整对照：[合同/术语表.md](合同/术语表.md)。

## 16. 常见卡点

| 现象 | 先查 |
|---|---|
| Agent 不让立项 | 禁售句还在原话里，或没回 `ban_ack` |
| 02 过不了门 | 主终点不是提及概率，或 need 相交，或因果主张不是默认描述 |
| 07 过不了门 | 诊断预算里出现干预/改页，或报价没排除 L1 |
| 03 过不了门 | 冻结和章程对不上，或问法表 / 平台表与 need、平台不一致 |
| 冲刺写不了最终四选一 | 等待时钟没满，或在 03 就想写「受控前后」 |
| 关键门批不了 | 只签了一个人，或同一个人签了两个角色 |
| 交付收不了 | 用了共享出数目录，或校验和、身份对不上冻结 |
| 结不了项 | 中转还有待取，或想在结项里重开 L1 |
| 不知道文件放哪 | 人交的进 inbox 或 `原始/{站}/`；正式件只在过门后进 `正式/现行/` |
| Agent 一开口讲完整本 SOP | 打断它，只问当前站「先做、我交什么、放到哪」 |
